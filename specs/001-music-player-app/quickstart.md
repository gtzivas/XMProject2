# Quickstart: Music Player App Validation Guide

**Phase**: 1 — Design
**Date**: 2026-07-02
**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md)

This guide describes how to set up the project, run it, and validate that each user story
works end-to-end. It is a validation/run guide — not an implementation guide. Full
implementation details are in [data-model.md](data-model.md),
[contracts/](contracts/), and `tasks.md` (generated by `/speckit.tasks`).

## Setup

```bash
# 1. Clone / enter the project
cd <repo-root>

# 2. Install JavaScript dependencies
npm install

# 3. iOS — install native pods
cd ios && pod install && cd ..

# 4. Android — no extra step (Gradle handles native deps)

# 5. Start Metro bundler (keep running in a separate terminal)
npm start
```

---

## Run

```bash
# iOS Simulator (default — iPhone 15)
npm run ios

# iOS — specific simulator
npm run ios -- --simulator "iPhone 15 Pro"

# Android Emulator (must be running in Android Studio first)
npm run android

# Physical device (iOS — requires Apple Developer account + provisioning profile)
npm run ios -- --device "My iPhone"
```

## Validation Scenarios

The scenarios below map directly to the acceptance criteria in [spec.md](spec.md).
Perform them in order; earlier stories are prerequisites for later ones.

---

### Story 1: Core Playback Controls (P1 — MVP)

**Setup**: Have at least one audio file (MP3 or AAC) accessible to the app.
On iOS: ensure the file is in the iOS Files app or the device music library.
On Android: place an audio file in `Downloads/` or `Music/`.

| # | Action | Expected outcome |
|---|--------|-----------------|
| 1.1 | Launch the app and navigate to the Library screen | At least one track appears within 5 seconds |
| 1.2 | Tap any track | Track begins playing; progress bar advances; track title and artist display on Now Playing screen |
| 1.3 | Tap the Pause button | Playback stops; progress bar freezes at current position |
| 1.4 | Tap Play again | Playback resumes from the same position |
| 1.5 | Drag the seek bar to a new position | Audio jumps to the dragged position and continues playing |
| 1.6 | Adjust the volume slider to 50% | Audio output level decreases noticeably |
| 1.7 | Add 2+ tracks to the queue; tap Next | The following track starts playing |
| 1.8 | Tap Previous within the first 3 seconds of a track | Returns to the previous track |
| 1.9 | Tap Previous after 3+ seconds into a track | Restarts the current track from 0:00 |
| 1.10 | Lock the device while a track is playing | Audio continues; lock screen shows track title, artist, and play/pause controls |

---

### Story 2: Music Library Browse & Select (P2)

**Setup**: Have 5+ audio files with varied artist and album metadata on the device.

| # | Action | Expected outcome |
|---|--------|-----------------|
| 2.1 | Open the Library screen | All detected audio files are listed with title, artist, and album |
| 2.2 | Switch to the Albums tab | Tracks are grouped by album; each group shows the album name |
| 2.3 | Switch to the Artists tab | Tracks are grouped by artist |
| 2.4 | Tap any track in the library | Track is loaded and begins playing |
| 2.5 | Type a partial track title into the Search bar | Matching results appear within 1 second |
| 2.6 | Type a partial artist name into Search | Tracks by that artist appear in results |
| 2.7 | Clear all audio files from the test device; relaunch the app | Library screen shows an empty-state message with guidance |

---

### Story 3: Playlist Management (P3)

**Setup**: Library must be populated (Story 2 setup). Story 1 must be working.

| # | Action | Expected outcome |
|---|--------|-----------------|
| 3.1 | Tap "New Playlist" and enter a name | Playlist appears in the Playlists screen |
| 3.2 | Long-press a track → "Add to Playlist" → select the new playlist | Track count on the playlist increases to 1 |
| 3.3 | Add 2 more tracks to the playlist | Playlist shows 3 tracks in insertion order |
| 3.4 | Open the playlist and tap the second track | Playback begins from the second track and continues through the list |
| 3.5 | Long-press a track row and drag to reorder | Tracks reorder; new order persists after navigating away and back |
| 3.6 | Rename the playlist | New name appears everywhere the playlist is referenced |
| 3.7 | Delete the playlist | Playlist is removed from the list; tracks remain accessible in the library |

---

### Story 4: Persistent Playback State (P4)

**Setup**: Stories 1–3 must be working.

| # | Action | Expected outcome |
|---|--------|-----------------|
| 4.1 | Play a track; let it reach position 1:00–2:00 | Track is playing |
| 4.2 | Force-quit the app (swipe away from app switcher) | App exits |
| 4.3 | Relaunch the app | The same track is loaded; position is within ±2 seconds of where it was |
| 4.4 | Enable shuffle mode; force-quit and relaunch | Shuffle is still enabled after relaunch |
| 4.5 | Set volume to ~30%; force-quit and relaunch | Volume is restored to ~30% |

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| Library empty on iOS | Music library permission not granted | Settings → Privacy → Media & Apple Music → allow the app |
| Library empty on Android 13+ | `READ_MEDIA_AUDIO` permission denied | Settings → Apps → Music Player → Permissions → Music and Audio → Allow |
| Audio not playing in background on iOS | `UIBackgroundModes` not set in `Info.plist` | Ensure `audio` is in `UIBackgroundModes`; this is set up in `react-native-track-player` docs |
| Metro bundler "cannot connect" | Metro not running | Run `npm start` in a separate terminal |
| Pod install fails | CocoaPods outdated | `sudo gem update cocoapods && pod install` |
| Gradle sync fails | Android SDK not configured | Open `android/` in Android Studio and let SDK sync complete |
